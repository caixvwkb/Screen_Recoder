# 2.1 UI 重构设计（2026-09-07 至今）——建模级变更

> 版本定位：放弃自绘体积优势，采用第三方控件库重构前端；功能逻辑不动，仅重做表现层。
> 这是除 1.0 外唯一一次建模级变更，按树状记录。

## 1. 背景与选型
- 旧 UI（1.0 文字硬约束驱动）代码全堆在一个文件、维护困难 → 整体重构前端
- 控件库：**PySide6-Fluent-Widgets**（zhiyiYo，Windows 11 Fluent 风格，纯 Python + QSS，
  打包无额外二进制负担）
- 注意：本项目是 PySide6 后端，装 `PySide6-Fluent-Widgets`（包名 qfluentwidgets），
  不是 PyQt-Fluent-Widgets（PyQt5-only，会冲突）

## 2. 界面结构
### 2.1 主窗口与导航
- FluentWindow + **5 个导航页**（视频 / 散图 / PDF / OCR / ASR），默认窗口约 1440×900
- 导航栏右键管理：隐藏 / 恢复 / 删除自定义页
- 底部「关于软件」页（圈 i 图标）：软件信息 / 作者 Caixvwkb / 版本信息

### 2.2 功能页结构（每页统一）
- 滚动区 + 标题卡 + 功能折叠卡 + 状态脚注
- 折叠卡可展开收起（带动画）；子选项卡排版：**一行文字、一行按钮**
  （避免按钮被文字挡住渲染不全）

### 2.3 录制区域卡
- 三个子功能：**全屏 / 框选录制范围 / 应用窗口捕获**
- 应用窗口捕获：只录制运行中 APP 窗口实际显示的内容和大小，不被其他画面遮挡
  （PrintWindow 取窗口真实渲染内容）；窗口无效（已关闭）时提示重新选择

### 2.4 设置页（集中管理）
- 通用：保持置顶、深色模式（默认浅色）、录制/截图/PDF 自动带 OCR 与 ASR 的开关
- 模型：OCR/ASR 模型目录卡（每张两个按钮：选择目录 + 快速打开目录）
- 输出：OCR/ASR 输出目录卡（合并一张卡，可自定义汇总文件夹名称）
- 快捷键：个性化编辑 + 持久化（默认定稿：选区 Ctrl+A / 开始 Ctrl+S / 停止 Ctrl+P / 截图 Enter）

### 2.5 深浅主题
- 深色模式开关（默认浅色，不跟随系统），切换即时生效

## 3. 工程化约束
### 3.1 UI 层拆分
- ui/widgets.py 通用组件 + ui/pages/*.py 页面控制器（5 个 Mixin）
  + mainwindow_fluent.py 只留窗口框架 + 导航 + 装配
- 新文件必须进 pyproject.toml `[tool.pyside6-project].files`，否则 Qt Creator 面板看不到

### 3.2 绿色化
- 配置、缓存、默认输出、模型**全部随程序目录**（打包后=exe 同级；源码=项目根），拷走即用
- settings.json 在程序根；缓存统一 `cache/`；首次运行自动创建默认配置；
  旧 %AppData% 配置首次启动自动迁移

# 迭代需求流水（按时间标签平铺）

> 除 1.0 初始设计与 2.1 UI 重构外的所有迭代需求，按时间一条条平铺。
> 新需求到来：追加到对应日期（新日期新建小节），每条 = 一句话描述 + 关键约束。

## 2026-09-03（1.x）
- **[全局热键]** 后台全程待命：焦点在其他程序（浏览器/编辑器/考试系统）时按 Enter 截图也生效。
  设计约束：Enter 注册为全局热键但**只在手动批量截取会话期生效**（结束自动注销，
  避免后台常驻抢走所有程序的 Enter）；Ctrl+A/P/B 保持应用内快捷键（系统通用键全局化会破坏其它程序）；
  注册必须用真实窗口句柄（NULL 句柄 Qt6 收不到线程消息）；热键冲突静默跳过不崩溃。
  防作弊考试系统场景：目标进程管理员权限 + 低级键盘钩子时，本软件需**管理员身份运行**才生效
- **[AI 友好输出]** 三层设计：① PDF 元数据（Title/Author/Creator）② 配套说明.md
  （每张图 + OCR 文字）③ PDF 隐形文字层（透明文字，视觉不可见但 AI/pdftotext 可提取）
- **[性能与状态反馈]** 最终输出（PDF 导出 / OCR / ASR 批量）一律**后台线程**处理，主界面不卡；
  底部状态栏实时显示"处理中"文字与进度；处理中禁止重复触发（状态锁）；
  关闭程序时等待后台线程安全退出（最长 5 秒）
- **[OCR 可选项]** OCR 文字识别做成**可开关**（选项菜单勾选），关闭后：纯 PDF 输出
  （无文字层、无说明.md），元数据仍保留
- **[OCR 识别页（第 4 个 Tab）]** 选文件夹批量识别图片/PDF，**每个文件一个 `<文件名>_说明.md`**；
  PDF 有文字层直接提取、扫描件自动逐页渲染再 OCR；后台线程处理界面不卡；设置持久化
- **[并行加速]** 「合并图片为一个 md」选项（默认勾选，减少文件数；PDF 仍各自生成）；
  OCR 并发数选项（1~8，默认 min(4, CPU核//2)）：常驻线程池（引擎一次加载长期复用，
  消除"每次等很久"）；每引擎限 1 推理线程（避免桌面卡顿）

## 2026-09-07（2.0）
> 版本定位：AI 可读文本产出链路完整落地（OCR 外置模型 + ASR 语音转写 + 统一输出目录选项）。
- **[OCR 模型外置]** 模型**不进包**（Nuitka standalone 不收集 .onnx/二进制模型文件，
  打包版 OCR 失效根因）；模型放 **exe 同级 `models/ocr/`**（外置目录热加载），
  缺失时回退 rapidocr 包内模型；设置页可指定模型目录路径；
  模型来源可区分：OCR（rapidocr）/ ASR（sherpa-onnx）分目录，互不干扰
- **[ASR 识别页（第 5 个 Tab）]** 引擎 sherpa-onnx + SenseVoice（中英日韩粤，离线），
  模型外置 `models/asr/`（无包内兜底）；音频（wav/mp3/m4a/flac/ogg…）与视频
  （mp4/mkv/avi/mov/webm）批量转写，每文件一个 `<文件名>_语音转写.md`；
  非 wav 格式走自带 ffmpeg 转码；选项与 OCR 页对齐（并发数 / 自动一站式 /
  是否扫描子文件夹 / 处理格式白名单 / 输出独立文件夹）
- **[输出目录]** OCR/ASR 批量输出：可勾选**输出到独立文件夹**（默认名「输出」可自定义）
  ——多文件汇总一处；不勾选 = 散在源文件旁边

### 2.4（2026-09-08）：视频档位收敛 + 音画同步方案定稿
- **背景**：60fps 以上档位（120/144/240）实测音画时间戳对不上——视频容器帧
  PTS 是均匀推算值（n/fps），真实抓帧受 Windows sleep tick 粒度（15.6ms 动态
  tick）+ 线程调度抢占影响，帧间隔 std 3.7~10.5ms、偶发最大 31~63ms，音频是
  连续真实采样 → 局部音画偏差。测试结论：timeBeginPeriod(1) 在本机无效；
  dxcam 后台 pacing（waitable timer）同样受 tick 影响；忙等（含 sleep(0) 版）
  实测更差（GIL/编码抢占，std 升到 6.4~7.5ms）。
- **决策（用户拍板）**：
  1. **录制档位最高 60fps**——移除超清 120 / 旗舰 144 / 极限 240 三档，保留
     流畅 24 / 均衡 30 / 高清 60；删除显示器物理上限检测与超上限禁用逻辑。
     60fps 下无音画同步问题。
  2. **删除两段式 sleep / 线程优先级优化**——还原为简单目标时刻 sleep
     （delay>0 则 sleep），后台 dxcam target_fps 还原 max(60, fps)；删除
     录制线程 ABOVE_NORMAL 优先级设置。
  3. **删除「音频偏移（音画微调）」功能（含 UI）**——移除视频页音频设置卡的
     音频偏移输入行、settings 键 audio_offset_ms、ScreenRecorder 的
     audio_offset_ms 参数、audio_capture.apply_audio_offset 函数。
- **保留**：帧队列等待反压（不丢帧）、fix_video_fps 时长对齐、mux 不加
  -shortest（尾部保留只有声音段）、同步诊断日志（首帧延迟/帧间隔/音频起点
  延迟）、时长诊断日志（编码帧/循环耗时/实际帧率）。

# 2.3（2026-09-08）：ASR 核心可用化（长音频分段修复 + 输出改 TXT）

> 定位：ASR 是用户日常最高频功能，本次解决「课堂录音全部无法转录」的硬伤。

### 2.3.1 长音频 OOM 修复（已实现）
- **现象**：任意 mp3/m4a（课堂录音，几十 MB ≈ 半小时级）转写全部失败，输出 0 字；
  日志 BFCArena::AllocateRawInternal Failed to allocate memory for requested buffer
  of size 73666645248（73GB / 146GB / 160GB / 179GB 递增）。
- **根因**：	ranscribe() 把**整段音频**一次 ccept_waveform 喂给 SenseVoice，
  encoder 的 self-attention 矩阵 L×L 随音频时长平方增长——几分钟音频 → 特征序列
  数十万 → 中间 buffer 数十 GB，onnxruntime 直接 OOM 返回空结果。
- **方案（sherpa-onnx 对 SenseVoice 长音频的标准做法）**：**分段识别**——
  单段 ≤30s（SenseVoice 训练窗口上限），段间重叠 1s（避免切在词中间丢字），
  逐段 create_stream + decode_stream 后拼接；末段不足 1s 跳过（已被重叠区覆盖）。
- **验证**：32MB 课堂 mp3（约 40 分钟）→ 133 段、13309 字完整转写，OOM 消失 ✓；
  耗时 277s（SenseVoice int8 单线程固有成本，多文件靠并发数并行摊平）。

### 2.3.2 ASR 输出格式 md → txt（已实现）
- **需求**：语音转写输出从 <文件名>_语音转写.md 改为 <文件名>_语音转写.txt——
  纯文本适配性最好（任何编辑器/其他工具/AI 直接可读，无需处理 Markdown 符号）。
- **实现**：sr.write_asr_md → write_asr_txt（内容=纯转写文字，无标题/元信息头）；
  export_worker.ASRWorker 同步；ASR 页说明文案同步（md → txt）。
- **注意**：OCR 侧仍输出 md（图片/结构说明需要 Markdown），仅 ASR 改 txt。
### 2.3.3 并发数改为「段级并行」（已实现）
- **背景**：2.3.1 分段修复后，单文件长音频内部仍是**串行**逐段推理——32MB mp3
  耗时 277s，并发数只并行「文件」，单文件场景（用户常态）并发完全闲置。
- **方案**：把「文件 × 分段」**拍平成独立识别任务**，统一线程池按并发数消费——
  并发数同时作用于段与多文件（多文件自然同池并行），每工作线程独立识别器
  （thread-local，onnxruntime 释放 GIL 真并行），段完成后按段起点排序合并，
  文件所有段完成即聚合回调（进度）+ 写 txt。
- **实现**：sr.transcribe_parallel_segments(files, max_workers, on_file_done)
  （解码阶段也并行，m4a/视频 ffmpeg 转码同步摊平）；export_worker.ASRWorker

### 2.3.4 ASR 双进度 + 段级日志（已实现）

### 2.3.5 ASR 双进度修正 + 时间戳字幕输出（已实现）

### 2.3.8 ASR 并行与输出重构：按文件即时输出 + 多文件均匀并行（已实现）
- **问题**：①所有文件识别完成才统一写 txt——中途异常已识别内容全丢、
  进度清空；②段任务按解码完成顺序提交，先解码完的文件独占线程池，
  观感是一个文件一个文件处理。
- **重构**（asr.py / export_worker.py / asr_page.py）：
  - **两阶段**：全部文件先并行解码，全部就绪后才提交识别任务；
  - **交错提交**：按文件轮换提交段任务（f1s1, f2s1, f1s2, f2s2…），
    多个文件段同时进池、均匀推进（实测 2 文件日志段归属交替出现）；
  - **按文件即时完成**：某文件全部段完成 → 立即聚合并回调 on_file_done →
    立即写 txt + 文件进度 + 浮窗提示（不等待其他文件）；
  - **失败隔离**：解码失败/识别失败的文件不触发文件完成事件，结束时
    计入失败数；已完成文件照常输出，互不影响（实测：2 成功 1 失败）。
- **验证**（60s+90s+伪造文件，3 并发）：
  - 事件序列：_fa 最后一段完成 → 立即 文件1/3 完成；_fb 后续段完成后
    → 文件2/3 完成（完成事件分散出现，非集中爆发）；
  - 段日志交错：段1/7(_fb) 段2/7(_fa) 段3/7(_fa) 段4/7(_fa) 段5/7(_fb)…；
  - finished=(2,1)，两个 txt 均正常生成。
